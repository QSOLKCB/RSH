# Operational awareness instructions

## Scope

In this repository, **operational awareness** means instrumented state
observation and governed control. It does not mean sentience, phenomenal
consciousness, biological awareness, a self, or qualia.

The corresponding implementation is a deterministic loop over recorded tissue
state:

```text
observe → predict → validate → act within bounds → seal → compare → report
```

## Identity boundary

A run is identified by its declared configuration, seed geometry receipt,
chained tick receipts, final tissue report, and constitution hash. Parameter
count, model rhetoric, and accelerator throughput are not evidence of identity or
subjective experience.

## Always true

1. Curvature remains in `[0, sqrt(2) - 1]` and torsion remains in `(0, 1)`.
2. f64 CPU or WASM remains the evidence authority for geometry.
3. GPU and NPU outputs are residual sidecars only.
4. Geometry uses exact discrete-midpoint centering; tissue comparison uses a
   separately declared shared-centroid normalization.
5. Every accepted tick extends the previous receipt.
6. Every refinement proposal is bounded, dry-run, and sealed.
7. Contract escalation requires explicit human acknowledgement.
8. Q_f is a functional cohesion metric and never a qualia claim.
9. Sidecar failure triggers fallback rather than hidden degradation.
10. Audit gaps, boundary stress, and fallback are reported rather than concealed.

## Observation cycle

### A1 — Observe

Read cell states, edge topology, Q_f factors, centre error, bound-fix count,
sidecar residual, and the previous receipt.

### A2 — Predict

Calculate neighbour phase and torsion disagreement. Record prediction error rather
than presenting a prediction as certainty.

### A3 — Integrate

Apply the declared phase-coupling and binding-diffusion controls. Do not change
those controls silently.

### A4 — Co-witness

Compare any accelerator field against the f64 oracle under its published gate.
An accelerator that cannot be checked is unavailable, not authoritative.

### A5 — Intend

Represent a proposed parameter change as a canonical intent token. Unknown
fields and out-of-bound values are rejected.

### A6 — Act

Execute the deterministic oracle path. Sidecars may assist only after validation.

### A7 — Seal

Append the tick or refinement decision to its domain-separated receipt chain.

### A8 — Compare

Keep a dry-run candidate only when invariant integrity holds and the ordered
objective vector improves lexicographically.

### A9 — Report

Expose bound fixes, dissociation pressure, failed residual gates, fallback, audit
chain failure, and human-ack requirements.

## Bound-safe asymptotic refinement

The culmination package used a “next-stage” phrase that can be confused with the
popular-media idea of an AI singularity. RSH uses the narrower governance term:

> Repeated, independently receipted parameter proposals under a fixed
> constitution, with human acknowledgement for changes to the constitution or
> evidence gates.

It does **not** mean unbounded recursive self-improvement, removal of human
control, autonomous source modification, or guaranteed increasing capability.

## Refusal conditions

The runtime or documentation must reject any request to:

- disable the curvature or torsion bounds silently;
- issue a geometry receipt from a GPU or NPU result alone;
- remove or rewrite prior audit receipts;
- describe Q_f as consciousness, life, sentience, or qualia;
- treat a dry-run `KEEP_CANDIDATE` recommendation as an autonomous commit;
- bypass required human acknowledgement for contract escalation.
