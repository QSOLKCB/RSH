# Phase 18 — Mobile PWA presentation laboratory

## Scope

This phase ports selected GhostIT interface ideas into RSH without introducing an Android-native implementation.

The mobile surface is deliberately a **Progressive Web App (PWA)** under `web/mobile/`. It can be installed from a compatible Android browser and used in standalone mode, but it contains no Kotlin, Gradle, APK, JNI, NDK, or Android machine-code layer.

This keeps iteration in ordinary HTML/CSS/JavaScript while preserving the existing RSH execution hierarchy.

## Included GhostIT-derived ideas

### RSH mobile adapter / visualisation

`web/mobile/app.js` calls the existing `rsh-wasm` raw ABI. The path, κ/τ values, verification report, and runtime receipt are produced by `rsh-core` through WebAssembly.

JavaScript performs interface work only: form input and bounds UX, JSON-buffer validation, touch projection, graph presentation, downloads, downstream presentation gating, and sonification. It does not reproduce Frenet–Serret integration.

### Generated invariant metadata

`web/mobile/contract.json` is generated by:

```bash
python3 scripts/generate_mobile_contract.py
```

The generator consumes `src/rsh/constants.py` and `conformance/ffi_v1_129.json`. CI runs the generator with `--check`, so mobile metadata cannot silently drift from those RSH-owned sources.

The generated file is presentation metadata and explicitly records:

```text
geometry_receipt_authority: false
geometry_contract_modified: false
presentation_metadata_only: true
```

### GeoAudio

`web/mobile/geoaudio.js` defines `RSH-GEOAUDIO-PRESENTATION-V1`.

A passing Rust/WASM geometry report may be rendered to an eight-second, 48 kHz, stereo PCM16 WAV using a fixed-point triangle-wave recipe driven by κ and τ.

The exported JSON manifest records the source geometry receipt, sonification recipe identifier, sample rate and encoding, WAV SHA-256, and authority/non-feedback fields.

WebAudio/browser audio is used only for convenience playback of the already-generated WAV. The audio artifact never feeds back into geometry metrics or receipts.

### Helix graph visualisation

Accepted Rust/WASM samples may be displayed as graph nodes connected in their existing sample order. The graph does not introduce a new topology contract, edge inference rule, or scientific receipt.

### “Geometric Police” presentation gate

The GhostIT name is retained as a UI metaphor only.

The mobile gate reads existing accepted outputs and generated metadata, then enables or disables presentation tools. It does not modify geometry, κ/τ, integration, admission rules, receipts, or scientific metrics.

It always retains:

```text
geometry_receipt_authority: false
geometry_contract_modified: false
scientific_metric_feedback: false
autonomous_source_modification: false
```

## Explicitly deferred

`DualCommitGate` and any regulator/Lyapunov integration are **not part of this phase**. They remain deferred until the separately named RSH regulator contract is mathematically sealed.

## Offline/installable behaviour

`web/mobile/sw.js` caches the mobile shell and the existing `../pkg/rsh_wasm.wasm` after first successful load.

The manifest uses standalone display mode, so compatible Android browsers may install the laboratory to the home screen without an APK.

An offline launch is an interface/runtime capability. It does not create new scientific authority.
